<a id="compose-error"></a>

## สั่ง docker compose แล้ว error ทันที

| ข้อความ | สาเหตุ | วิธีแก้ |
| --- | --- | --- |
| เกี่ยวกับ `env_file` หรือ `required` | Docker Compose รุ่นเก่ากว่า 2.24 | อัปเดต Docker Desktop |
| `Cannot connect to the Docker daemon` หรือคล้ายกัน | ยังไม่ได้เปิด Docker Desktop | เปิด Docker Desktop แล้วรอจนพร้อม |
| `container name ... is already in use` | มี container ชื่อเดียวกันจากโฟลเดอร์อื่นค้างอยู่ | ไปที่โฟลเดอร์เดิมแล้วสั่ง `docker compose down` หรือลบ container นั้นใน Docker Desktop |

<a id="port-in-use"></a>

## port 3000 หรือ 27017 ถูกใช้อยู่

ข้อความประมาณ `port is already allocated` หรือ `address already in use`

| port | ใช้ทำอะไร | วิธีแก้ |
| --- | --- | --- |
| 3000 | เว็บ | ตั้ง `WEB_PORT` ตาม [เปลี่ยน port ของเว็บ](04-configuration.md#port) หรือปิดโปรแกรมที่ใช้ port นี้อยู่ |
| 27017 | ฐานข้อมูล MongoDB | มักเกิดเมื่อเครื่องมี MongoDB ติดตั้งอยู่แล้ว ให้สร้างไฟล์ `.env` ข้าง `docker-compose.yml` ใส่ `MONGO_PORT=27018` แล้วสั่ง `docker compose up -d` |

<a id="slow-build"></a>

## build นานมากหรือค้าง

- ครั้งแรกนานเป็นปกติ เพราะต้องดาวน์โหลด PyTorch และ package ของเว็บ
- ตรวจอินเทอร์เน็ต ถ้าหลุดกลางทาง สั่ง `docker compose up --build` ซ้ำได้ ระบบจะทำต่อจากที่ค้าง
- ครั้งต่อไปจะเร็วขึ้นมาก เพราะ Docker เก็บสิ่งที่ดาวน์โหลดแล้วไว้

## เว็บเปิดไม่ขึ้นหรือ container เว็บ restart วน

<a id="shared-db"></a>

## เปิดเว็บไม่ขึ้น ขึ้นว่า "ตั้งค่าไม่ปลอดภัย"

**ความหมาย:** ระบบเก็บรูปหรือไฟล์โมเดลลงดิสก์ของเครื่องนี้ แต่ `DATABASE_URL` เป็นฐานข้อมูลบนคลาวด์ (MongoDB Atlas) ที่เว็บจริงใช้ด้วย ถ้าปล่อยให้ทำงาน เว็บจริงจะเห็นประวัติและโมเดลที่ไฟล์อยู่บนเครื่องนี้ แล้วเปิดไม่ได้

**วิธีแก้:** ใช้ฐานข้อมูลของเครื่องนี้เอง — `docker compose up -d mongodb` แล้วตั้ง `DATABASE_URL=mongodb://localhost:27017/acne_db?replicaSet=rs0&directConnection=true` ใน `apps/web/.env` (ถ้าตั้งใจใช้ฐานข้อมูลร่วมจริง ๆ ตั้ง `ALLOW_SHARED_DB=true`)

[↑ สารบัญ](#toc)

<a id="admin-login"></a>

## เข้าด้วย admin@acne.local ไม่ได้

บัญชีเริ่มต้นถูกสร้างเฉพาะตอนที่ฐานข้อมูลยังไม่มีผู้ดูแลระบบ ดู log ของเว็บตอนเริ่มระบบ:

| log | ความหมาย |
| --- | --- |
| `[seed] สร้างบัญชีแอดมินเริ่มต้น: ...` | สร้างแล้ว ใช้อีเมลและรหัสผ่านตามที่ตั้งไว้ |
| `[seed] มีผู้ดูแลระบบอยู่แล้ว (...) ข้าม` | ฐานข้อมูลมีแอดมินอยู่ก่อนแล้ว ให้ใช้บัญชีนั้น |
| `[seed] อีเมล ... ถูกใช้โดยบัญชีที่ไม่ใช่แอดมิน` | มีคนสมัครด้วยอีเมลนี้ไปแล้ว จึงไม่ได้สร้างแอดมิน |

ถ้าจำรหัสไม่ได้และยอมเสียข้อมูลทั้งหมด: `docker compose down -v` แล้วเปิดใหม่

<a id="ai-error"></a>

## ขึ้นว่า "การประมวลผลรูปภาพขัดข้องที่ระบบ AI"

1. สั่ง `docker compose ps` ดูว่า `acne_ai` ทำงานอยู่
2. สั่ง `docker compose logs ai` ดูข้อความ error

| สิ่งที่เห็นใน log | สาเหตุ | วิธีแก้ |
| --- | --- | --- |
| `Invalid API Key` (403) | รหัสของเว็บกับ AI ไม่ตรงกัน | ใน Docker ระบบตั้งให้ตรงกันเอง ถ้าแก้ `AI_SERVICE_API_KEY` เอง ให้สั่ง `docker compose up -d` เพื่อเปิดใหม่ทั้งสองส่วน |
| `Failed to download ...` | AI โหลดไฟล์โมเดลจากเว็บไม่ได้ | ตรวจว่าเว็บทำงานอยู่ แล้วลองใหม่ |
| `Image path is not allowed` (400) | รันแบบไม่ใช้ Docker และโฟลเดอร์รูปของเว็บกับ AI ไม่ตรงกัน | ตั้ง `STORAGE_PATH` ใน `apps/ai/.env` ให้เป็นโฟลเดอร์เดียวกับฝั่งเว็บ หรือเว้น `STORAGE_PATH` ฝั่งเว็บให้ว่างเพื่อใช้ `apps/images` |
| error ตอนโหลดโมเดล | ไฟล์โมเดลไม่ใช่ชนิดที่รองรับ | ดู [ไฟล์โมเดลที่ใช้ได้](03-admin-guide.md#model-file) |
| (Render) `Instance … restarted` | หน่วยความจำของเครื่อง AI ไม่พอเปิดโมเดลหลัก (Render ฟรีมี RAM 512 MB) | ตั้งโมเดลที่เล็กกว่าเป็นโมเดลหลัก เช่น best.pt — โมเดลใหญ่ใช้กับ Docker หรือ Azure |

## อัปโหลดโมเดลไม่ผ่าน

| สาเหตุ | วิธีแก้ |
| --- | --- |

<a id="pip-launcher"></a>

## สั่ง pip แล้วขึ้น Fatal error in launcher

ตัวอย่าง: `Fatal error in launcher: Unable to create process using ...`

**สาเหตุ:** โฟลเดอร์ `venv` ถูกสร้างไว้ตอนโปรเจคอยู่ที่ path อื่น (เช่น เคยชื่อโฟลเดอร์อื่น หรือคัดลอกมา) ไฟล์ `pip.exe` จำ path เดิมไว้

**วิธีแก้:** เรียก pip ผ่าน python แทน

```bash
venv\Scripts\python.exe -m pip install -r requirements.txt
```

หรือลบโฟลเดอร์ `venv` แล้วสร้างใหม่ด้วย `python -m venv venv`

<a id="image-missing"></a>

## รูปในประวัติไม่แสดง / log ขึ้น ENOENT

ตัวอย่าง log ของเว็บ:

```
ENOENT: no such file or directory, stat '/app/images/xxxxxxxx.webp'
```

**ความหมาย:** ฐานข้อมูลมีประวัติรายการนั้นอยู่ แต่ไฟล์รูปไม่อยู่ในที่เก็บของระบบนี้ มักเกิดจากลบ volume `image_files` แต่ไม่ลบ `mongodb_data` หรือเคยรันระบบในเครื่องโดยต่อฐานข้อมูลของเว็บจริง (รูปอยู่ในเครื่องนั้น)

**ผลกระทบ:** รูปของรายการนั้นไม่แสดง ส่วนอื่นของระบบทำงานปกติ

**วิธีแก้:** ให้ผู้ดูแลระบบลบรายการนั้นในเมนู **ประวัติการวิเคราะห์ทั้งหมด** หรือปล่อยไว้ก็ได้ ถ้าเป็นข้อมูลที่ปนจากเครื่องอื่นจำนวนมาก นักพัฒนาใช้ `npm run db:cleanup` ล้างได้ (ดู `dev-docs/environments.md`)

<a id="anonymous-volume"></a>

## มี volume ชื่อเป็นตัวอักษรยาว ๆ ใน Docker

volume ที่ชื่อเป็นตัวเลขและตัวอักษร 64 ตัว เป็น volume ที่ Docker สร้างให้อัตโนมัติสำหรับเก็บไฟล์ตั้งค่าภายในของ MongoDB ไม่มีข้อมูลผู้ใช้อยู่ในนั้น

รุ่นล่าสุดตั้งชื่อ volume นี้เป็น `mongodb_config` แล้ว จึงไม่มีชื่อแบบสุ่มเพิ่มอีก volume ชื่อสุ่มที่ค้างจากก่อนหน้าและ **ไม่ได้ถูกใช้งานอยู่** ลบได้จากแท็บ Volumes ของ Docker Desktop

ข้อมูลจริงของระบบอยู่ใน volume ที่ชื่อลงท้ายด้วย `mongodb_data` **อย่าลบตัวนี้**
