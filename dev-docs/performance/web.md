# ผลทดสอบความเร็ว: ระบบเว็บ (ตอนใช้งานจริง)

> โฟลเดอร์ `dev-docs/performance/` เก็บผลทดสอบแยกตามช่วง ไฟล์นี้คือช่วงใช้งานระบบเว็บ ผลช่วงเทรนโมเดล AI จะอยู่ในไฟล์แยก

วัดเมื่อ 2026-10-04 โมเดลเดียวกัน (ไฟล์ `.pt` ขนาด 5.15 MB) วิเคราะห์ 3 รูปต่อสภาพแวดล้อม
ตัวเลขฝั่ง AI มาจาก log `[FastAPI Timing]` ของบริการ AI

## อ่านเวลาจาก log (ใช้วัดรอบต่อไป)

ทุกคำขอพิมพ์ log 1 บรรทัด มี **request id** ใน `[...]` — id เดียวกันทั้งเว็บและ ai (เว็บส่งให้ ai ทาง header `X-Request-ID`)
ค้น id นั้นใน Log stream / Log Analytics จะเจอทั้งสองบรรทัดของการวิเคราะห์ครั้งเดียวกัน ถ้ามีคนใช้พร้อมกันก็ไม่สับสน

```
# web (acne-web) — วิเคราะห์ 1 ครั้ง (ตัวอย่างบน Azure)
analyze timing [3f9c0a1b2d4e5f60]: auth 0.05s | read form 0.10s | check file 0.00s | find model 0.03s | upload 0.30s | ai request 2.40s (network/wake 0.49s) | save db 0.08s | total 2.96s | 2 detections | tta=true
# ai (acne-ai) — บรรทัดคู่กัน
predict timing [3f9c0a1b2d4e5f60]: image 0.04s | model 0.00s | inference 1.87s | total 1.91s | 2 detections | tta=True
# web — เปิดรูปในหน้าประวัติ (/api/images)
image timing [8a7b6c5d4e3f2a1b]: auth 0.05s | check owner 0.03s | read azure-blob 0.10s | total 0.18s | 245 KB
```

| ขั้น (`analyze timing`) | ทำอะไร |
| --- | --- |
| `auth` | เช็ค login + หา User ใน DB |
| `read form` | รับไฟล์รูปจากเบราว์เซอร์จนครบ (เน็ตผู้ใช้ช้า/รูปใหญ่ = นาน) |
| `check file` | ตรวจชนิด/ขนาด/เนื้อไฟล์ |
| `find model` | หาโมเดลหลัก (Active) ใน DB |
| `upload` | เก็บรูป (ที่เก็บดูจาก `web start: ... image=` — `azure-blob` / `vercel-blob` / `local`) ส่งขึ้นอย่างเดียว ไม่ได้โหลดกลับ · รวมการสร้างลิงก์ SAS ให้ ai (คำนวณในเครื่อง ~0 วินาที) |
| `ai request` | เรียก `POST /predict` จนได้ผล — เวลาแต่ละขั้นข้างใน ai ดูที่บรรทัด `predict timing` id เดียวกัน |
| `network/wake` | `ai request` − `total` ของ ai (ai ส่งมาใน header `Server-Timing`) = เครือข่ายระหว่างเว็บกับ ai + เวลาที่ ai ตื่นจาก scale-to-zero — หลายวินาที = ai เพิ่งตื่น |
| `save db` | คำนวณ severity + บันทึก `Analysis` + `Image` |
| `total` | ตั้งแต่รับคำขอจนพร้อมตอบกลับ (ไม่นับเวลาส่งรูปจากเบราว์เซอร์ก่อนเว็บเริ่มอ่าน) |

| ขั้น (`predict timing` ของ ai) | ทำอะไร |
| --- | --- |
| `image` | โหลดรูปจาก blob (ลิงก์ SAS / URL) หรือเปิดจากดิสก์ |
| `model` | โหลดโมเดล — ครั้งแรกดาวน์โหลดจาก `GET /api/models/[id]` ครั้งต่อไปใช้ cache (0.00s) |
| `inference` | YOLO ทำนาย |

| ขั้น (`image timing`) | ทำอะไร |
| --- | --- |
| `auth` | เช็ค login |
| `check owner` | ค้น DB ว่ารูปนี้เป็นของผู้ใช้คนนี้ (แอดมินข้าม) |
| `read azure-blob` / `read local` | เปิดรูปจาก Blob จนได้ stream / อ่านจากดิสก์ (Azure ไม่นับเวลาส่งไฟล์ให้เบราว์เซอร์จนจบ) |

**ระดับ log:** สำเร็จ = info · ช้ากว่า 10 วินาที = warn และต่อท้าย `| slow` · ล้มเหลว = error เช่น
`analyze failed [<id>]: step=ai request error=... | auth 0.05s | ... | total 30.01s` / `predict failed [<id>]: step=image status=404 error=Image not found | total 0.01s`
`step=` คือขั้นที่พัง

**ดูในเบราว์เซอร์:** `/api/analyze` และ `/api/images` ตอบ header `Server-Timing` (มาตรฐาน W3C) — DevTools → Network → เลือกคำขอ → แท็บ Timing จะเห็นทุกขั้น รวมขั้นข้างใน ai (`ai-image`, `ai-inference` ...)

ตอนเริ่ม container ทั้งสองฝั่งพิมพ์ `web start: commit ...` / `ai start: commit ...` ไว้เช็คว่า deploy รุ่นเดียวกันแล้ว

## สรุป

1. **Docker กับการรันในเครื่องเร็วพอกัน** หลังครั้งแรกใช้ราว 0.2 วินาทีต่อรูป Docker ไม่ได้ทำให้ช้าลงอย่างมีนัยสำคัญ
2. **Render ช้ากว่าเครื่องทดสอบราว 140–250 เท่า** (37–45 วินาที เทียบกับ 0.18–0.27 วินาที) โค้ดและโมเดลเป็นชุดเดียวกัน ความต่างจึงมาจากทรัพยากรเครื่องของ Render
3. **ครั้งแรกช้ากว่าเสมอในทุกสภาพแวดล้อม** (7–11 วินาทีบนเครื่องทดสอบ, 106 วินาทีบน Render) เพราะต้องโหลดโมเดลเข้าหน่วยความจำ
4. **การโหลดไฟล์โมเดลไม่ใช่ตัวช้า** มากสุด 4 วินาทีและเกิดครั้งเดียว
5. **ในโหมดรันในเครื่อง เวลาส่วนใหญ่อยู่ที่ฝั่งเว็บ ไม่ใช่ AI** ครั้งที่ 2 ผู้ใช้รอ 4.0 วินาที แต่ AI ใช้ 0.22 วินาที ส่วนที่เหลือเป็นการบันทึกรูป เรียกฐานข้อมูลภายนอก และโหมดพัฒนาของ Next.js

## ข้อจำกัดของการวัด

- วัดสภาพแวดล้อมละ 3 ครั้ง ยังไม่ใช่ค่าเฉลี่ยทางสถิติ
- รูปที่ใช้ในแต่ละสภาพแวดล้อมไม่ได้ควบคุมให้เป็นชุดเดียวกัน
- A และ B ใช้โมเดลคนละรายการในฐานข้อมูล แต่เป็นไฟล์เดียวกัน
- เวลาที่ผู้ใช้รอของ Docker ครั้งที่ 2–3 ไม่มีตัวเลข เพราะโหมด production ของเว็บไม่พิมพ์เวลาต่อคำขอ
